## 两份方法说明

- **形态十二图**：以颈线为起跑线，形态高度为步长，顺着突破方向迈步。第一目标迈一步、第二目标再迈一步。
- **六反指标观察**：形 → 量 → 换 → 叉 → 带 → 筹。环环相扣，缺一环都不动手。

## 数据来源

三页扫描工具都通过浏览器直接抓取公开行情接口：

- **腾讯**（`web.ifzq.gtimg.cn/appstock/app/fqkline/get`）—— 股票日线，CORS 全开、无每日限额。
  美股必须带交易所后缀（`usAAPL.OQ` 纳斯达克 ／ `usBABA.N` 纽交所），不带后缀只返回两根。
- **新浪期货 JSONP**（`stock2.finance.sina.com.cn/futures/api/jsonp.php`）—— 内盘 `InnerFuturesNewService.getDailyKLine`、外盘 `GlobalFuturesService.getGlobalFuturesDailyKLine`。
  支持自定义回调名，返回真函数调用，可跨域。
- **东方财富数据中心**（`datacenter-web.eastmoney.com/api/data/v1/get`）—— **基本面扫描页的 F10 数据唯一来源**。
  首选 `fetch()`：该接口**在请求带 `Origin` 头时**返回 `Access-Control-Allow-Origin: *`，
  且是简单 GET（无自定义头）→ 不触发预检。
  兜底 JSONP：它认 `callback=` 参数（**不是 `cb=`**，用 `cb=` 只返回裸 JSON）。
  **任意 Referer、甚至完全不带 Referer 都返回 200。**
  > ⚠ 探测 CORS 必须带 `Origin` 头——服务器不带就不回该响应头，会误判成「无 CORS」。第一次就踩了这个坑。
- **东方财富行情**：`push2his.eastmoney.com` 实测长期不可达，代码里保留为备用但实际不会命中。

均为前复权日线，成交量单位自动识别（科创板接口返回「股」，其余返回「手」）。
**不经过任何第三方服务器，全部计算在你的浏览器里完成。**

### 指数成分股

`select.html` 的「扫描范围」用东财 `RPT_INDEX_TS_COMPONENT`，按 `TYPE` 区分指数。
**TYPE↔名称的映射取自东财自己的前端代码**（`newstatic/js/other/index.js` 的下拉选项），不是猜的：

```
1 沪深300(300)  2 上证50(50)   3 中证500(500)  4 科创50(50)   5 中证A50(50)
6 中证A500(500) 7 中证1000(1000) 8 深证50(50)  9 中小100(100) 10 北证50(50)
11 上证180(180) 12 中证A100(100) 13 中证2000(2000)
```

> ⚠ `pageSize` 实测**上限 500** —— 中证1000 要 3 页、中证2000 要 5 页，必须翻页取，否则静默少一半。
> 实测校验：沪深300=300、上证50=50（权重第一是贵州茅台）、中证1000=1000、中证2000=2000，全部对上。

### 拿不到的数据（如实交代）

- **现货价格 / 基差**（＝现货 − 期货）：新浪、东财都没有可跨域调用的接口。**期限结构是基差最接近的替代** —— 它不是猜的，是市场自己在给不同月份的货定价。
- **库存／仓单：拿到了。** 上一版说「拿不到」是**我没找对表**。东财数据中心有 `RPT_FUTU_STOCKDATA`，
  字段 `ON_WARRANT_NUM`（仓单量）、`ADDCHANGE`（增减）、`UNIT`（单位），实测覆盖 **71 个品种**，历史期数完整。
  仓单＝交易所登记的标准仓单量，是库存最硬的代理；但它只含交割品，**不等于全社会库存**。**外盘没有这张表。**
  （另外注意：`SECURITY_CODE` 大小写不统一 —— 多数大写 RB/HC/AL，原油是 `sc` 小写，两种都要试。）
- **港美股的 PB**：腾讯行情第 46 位只有 A 股是市净率，港美股那一位是英文名。代码做了纯数字校验，拿不到就留空、该项不计入匹配度分母。
- **外盘的持仓量**：新浪外盘 K 线里 `volume` 与 `position` 实测恒为 0，所以外盘只能靠价格本身。
- **`hq.sinajs.cn` 实时行情**：非新浪来源的 Referer 一律返回 **403**，无法跨域取用。
- **美股／港股的财务报表：拿到了。** 东财这两张表是「长表」（一行一个科目），
  但**带中文 `ITEM_NAME`**，所以能按科目名透视成宽表：
  美股苹果 → 营业收入 3643.57 亿 / 主营成本 1855.75 亿 / 归母净利 1014.64 亿 / 每股收益 6.88；
  港股腾讯 → 营运收入 4012.43 亿 / 毛利 2296.98 亿 / 除税后溢利 1173.69 亿 / 每股摊薄盈利 12.417。
  `guide.html` 据此新增「财务报表要点」块（港美股各 11 个关键科目 × 近 6 期）。
  > ⚠ 报告期列表里年报／半年报／季报混在一起，**同比必须配「去年同期」而不是相邻一期** ——
  > 一开始拿相邻两期比，腾讯显示成 `+104.2%`，改成去年同期配对后是 `+10.1%`（正确）。

### K 线图的读法

- **底部横轴是日期**：首根标 `MM-DD`，末根标完整日期并加粗 —— 一眼就能确认这张图到哪天为止。
- **右上角有数据新鲜度标记**：`数据截至 2026-09-14（最近交易日）`。
  **若最后一根 K 线距今超过 5 天，会变成红色警告**：这只票多半停牌，或行情源没有更新。
  （不做这个提示的话，用户看着一张停在旧日期的图，只会以为工具在骗他。）
- **筹码分布按 A 股惯例着色**：<span>红＝现价下方的获利盘</span>、<span>绿＝现价上方的套牢盘</span>。红赚绿亏。
- **F10 基本面的三家实测**：新浪 `CorpSummaryService.*` 一律 `Service not valid`、F10 页面是 HTML 且无 CORS；
  腾讯 `FinanceController` / `HkFinanceController` 均 `Can't load controller`。**只有东财走得通。**
  行情与 K 线仍然全部走腾讯，一个字节没改。

### 三个容易算错的坑（已在代码里钉死）

- **主营构成的占比字段是「分数」不是「百分数」**——用茅台／五粮液／中国船舶三家验证，各产品占比相加恰好 `= 1.0000`，所以显示时要 ×100。毛利率字段同理。
- **ROE 是年内累计值**，季报之间不能直接比大小；要比就比同一行的「同比」。
- **`REG_CAPITAL` 同名不同义**：A股是数字（单位**万元**），港股是字符串 `'1000000 HKD'`，美股没有这个字段。直接除以 10000 会在港股得到 NaN。
- **十大流通股东的「较上期」是混合文本**：`'新进'` / `'不变'` / `'-520897'`，直接 `Math.round()` 会得到 NaN。

## 关键口径

| 项 | 定义 |
|---|---|
| **筹码分布** | 每根 K 线旧筹码按 `(1 − 当日换手率 × A)` 衰减；当日成交量按**三角形**铺在 [最低, 最高] 之间，峰值在均价 `(H+L+2C)/4`。A 默认 1.0 |
| **压力位** | 从现价往上累计筹码到 **20%**（压力位1）／**50%**（压力位2）的价位 |
| **支撑位** | 从现价往下累计 **10%** 筹码的价位；不足 10% 判「无支撑」 |
| **协调强度（0~1）** | 筹码单峰程度、交易活跃度、支撑清晰度 三项平均。越高说明这个价位共识越强 |
| **MACD 状态** | 12/26/9 的柱是否 > 0；另按 `|MACD| ÷ 自身近 250 日 |MACD| 中位数` 分级：≥1.5 强／≥0.7 中／<0.7 弱（弱＝「门虚掩」，等同没转多） |
| **入场／止损** | 入场用现价（不假设回踩一定来）；止损＝支撑位下方一个波动缓冲（近 20 日平均振幅 × 2.5，下限 3%） |
| **目标价** | 只认筹码压力位。上方无压力位时**不给目标、也不给盈亏比**——不硬造数字 |

**MACD 实测依据**（17 只 × 8516 根 K 线，10 日持有）：

| 信号组 | 10日均 | 胜率 | 样本 | 结论 |
|---|---|---|---|---|
| 含慢档金叉 | +2.89% | 61% | 96 | **显著**（t=2.15，p≈0.03） |
| 不含慢档 | +0.39% | 45% | 354 | 等于随机（基准 +0.56%） |
| 快档 8/17/5 单独金叉 | +0.20% | 46% | 146 | 无 alpha |

> 结论：决定信号质量的是「**最慢的那一档在不在**」，不是「有几档金叉」。

### 一键发布

双击 **`~/Desktop/更新到GitHub.command`**。它会自己走完：

```
① 校验 token
② fetch 对齐本地分支            ← 防止历史分叉
③ 检测改动，没有就退出
④ 选通道：
     github.com 可达  → git commit + git push     （历史干净）
     被阻断           → api.github.com 的 Git Data API
⑤ 完成后再把本地对齐到远端
⑥ 每 8 秒探测一次，直到线上字节与本地 sha 一致才报「已上线」
```

**它只在确认线上内容与本地逐字节一致后才算成功**，不会出现"推上去了但其实没生效"。

### token

每次发布需要一个 GitHub Personal Access Token，**只勾 `repo` 一项**即可：

1. 打开 <https://github.com/settings/tokens/new>
2. Note 填「36wx-ta 更新」，Expiration 选 7 days
3. 勾选 `repo`
4. Generate → 复制 `ghp_` 开头那串
5. 存成 `~/Desktop/gh-token.txt`

存好后再双击一次工具即可。**token 不写进工具代码、不进 git 配置、不回显**；git 通道里通过 600 权限的临时凭据文件传递，用完立即删除。
**发完就去 <https://github.com/settings/tokens> 把它 Revoke 掉。**

### 为什么要两个通道

本机网络对 `github.com` 存在 **SNI 阻断**——TCP 握手能过，TLS 层被丢。症状是 `git push` 报 `Error in the HTTP2 framing layer`，或 `curl https://github.com` 长时间返回 `000`。

但 `api.github.com` 一直是通的（另一个边缘 IP，没被拦）。所以阻断发生时改走 **Git Data API**：

```
POST /git/blobs   × N     每个文件算 sha
POST /git/trees           挂到 base_tree 上
POST /git/commits         带 parent
PATCH /git/refs/heads/main
```

效果与 `git push` 完全等价——`git push` 底层调的就是这几个接口。

| 症状 | 处理 |

## 风险与限制

- 所有阈值默认值都是**统计推断**（cf I），不是定理。样本不足 250 根时不要采信。
- 筹码分布算的是「成交在什么价位堆积」，**测不出持有人身份**，不能据此判断主力是否吸筹。
- 筹码衰减系数 A 是敏感参数，换 A 后结论会变，不要跨 A 值比较。
- 界面刻意**去掉了 ATR**：所有对外口径改用筹码位阶与价格百分比。ATR 仅作内部统计归一化的量纲。
- **不构成任何投资建议。市场有风险，投资需谨慎。**
